# Приватность и 152-ФЗ

## Коротко

Браузер **не собирает персональные данные**. Нет телеметрии, аналитики, отчётов об ошибках. Всё работает и хранится **только на устройстве пользователя**.

## Что где хранится

### Локальные файлы (папка `userData`)

| Файл | Что внутри | Когда создаётся |
|---|---|---|
| `bookmarks.json` | Закладки и папки | При добавлении закладки |
| `history.json` | История посещений | При навигации (кроме приватных вкладок) |
| `downloads.json` | Список загрузок | При скачивании файла |
| `settings.json` | Тема, акцент, порядок кнопок тулбара, настройки | При изменении настроек |
| `session.json` | Открытые вкладки для восстановления | Если включено восстановление сессии |

**Пути:**
- macOS: `~/Library/Application Support/browser-project/`
- Windows: `%APPDATA%\browser-project\`
- Linux: `~/.config/browser-project/`

### Сессия Chromium

Cookie, кэш, localStorage, IndexedDB сайтов — хранятся во встроенной сессии Chromium там же, в `userData`. Отдельной приватной сессии — во временной, очищается при выходе.

**Ограничение размера кэша:** кэш Chromium ограничен **100 МБ** через `--disk-cache-size`. При превышении Chromium автоматически чистит лишнее. Дополнительно в настройках есть кнопка **«Очистить кэш»** для ручной очистки в любой момент.

### Данные, которые НИКОГДА не сохраняются на диск

| Данные | Где живут |
|---|---|
| «Недавно закрытые» вкладки | Только в RAM, стираются при выходе |
| PDF-документы во вьювере | Только в RAM, освобождаются при закрытии вкладки |
| Статистика блокировки трекеров | Только в RAM, сбрасывается при перезапуске |
| Кэш подсказок DuckDuckGo | Только в RAM, TTL 5 минут |
| Решения по разрешениям | Только в RAM, сбрасываются при перезапуске |

### localStorage

Используется для UI-настроек (тема до отрисовки страницы, размер шрифта в Reader Mode, ярлыки на стартовой). Не содержит персональных данных.

## Чего НЕТ в проекте

- ❌ Телеметрии (никаких отчётов о действиях пользователя)
- ❌ Аналитики (нет Google Analytics, Yandex Metrica и т.п.)
- ❌ Автоматических отчётов об ошибках (нет Sentry, Bugsnag)
- ❌ Аккаунта пользователя (нет регистрации, входа)
- ❌ Синхронизации с облаком (все данные только локально)
- ❌ Своего сервера (нет API, к которому шлём данные)
- ❌ Динамических списков трекеров (не делаем регулярных запросов к внешним серверам)

## Какие внешние запросы делает браузер

Ровно два:

1. **DuckDuckGo Autocomplete API** — `https://duckduckgo.com/ac/?q=...`
   - Когда: при вводе в поисковую строку
   - Что отправляется: только текст запроса
   - Что НЕ отправляется: идентификаторы, куки, что-либо о пользователе

2. **DuckDuckGo Favicon Service** — `https://icons.duckduckgo.com/ip3/...`
   - Когда: при показе закладки, истории или ярлыка
   - Что отправляется: только домен сайта (например, `github.com`)
   - Что НЕ отправляется: идентификаторы, куки

Оба запроса — без аутентификации, без пользовательских токенов.

## Соответствие 152-ФЗ

**Федеральный закон № 152-ФЗ «О персональных данных»** регулирует деятельность **операторов персональных данных** — тех, кто собирает, хранит, обрабатывает и передаёт ПД.

**Мой браузер не является оператором ПД, потому что:**

1. **Не собирает** ПД — нет форм регистрации, нет телеметрии, нет логирования действий
2. **Не обрабатывает** ПД — вся работа с данными (cookie, история, закладки) происходит **на устройстве пользователя** без участия разработчика
3. **Не передаёт** ПД третьим лицам — нет серверов, к которым шлём данные
4. **Не имеет доступа** к ПД — данные хранятся в `userData`, разработчик их не видит

**Принцип локальной обработки:** все данные, которые собирает браузер как инструмент, остаются в его песочнице на устройстве. Пользователь сам решает, что хранить, что удалить.

### Cookie и 152-ФЗ

Cookie, которые сохраняют сайты в браузере:
- Хранятся в изолированной сессии Chromium
- Не логируются, не отправляются разработчику
- Управляются самим пользователем через **Настройки → Приватность → Cookie-менеджер**

Пользователь может:
- Просматривать cookie по доменам
- Создавать, редактировать, удалять любые cookie
- Полностью очищать cookie одним нажатием
- **Полностью очищать данные сайтов** (cookies + localStorage + IndexedDB + service workers + кэш) одной кнопкой

### Приватный режим

В приватных вкладках используется **отдельная сессия Chromium** с изолированными cookie, кэшем и localStorage. При выходе из браузера данные приватной сессии **полностью очищаются** — гарантированно, через `before-quit` с `await clearPrivateData()`. Дополнительно очистка запускается при следующем запуске — на случай краша или принудительного завершения процесса.

История посещений в приватном режиме **не записывается**. Приватные вкладки **не попадают в «Недавно закрытые»** — чтобы их URL не утёк в меню.

### Блокировка трекеров

Браузер блокирует 200+ известных трекерных и рекламных доменов (Google Analytics, Facebook Pixel, Yandex Metrica и др.) через `webRequest.onBeforeRequest`. Заблокированные запросы **не отправляются** никуда — они отменяются до выхода из приложения.

Список трекеров — статический, лежит в `src/main/tracker-list.js`. **Не загружается из интернета** — это осознанное решение: динамические списки делают регулярные запросы к внешним серверам и раскрывают IP пользователя.

### Защита от `data:` в mainFrame

Все переходы на `data:`-URL в главном фрейме блокируются на уровне сессии через отдельный обработчик `webRequest.onBeforeRequest({ urls: ['data:*'] })`. Эта защита **работает всегда**, независимо от настроек блокировки трекеров.

## Что говорит разработчик

> «Проект не собирает пользовательские данные, не имеет серверной части, не передаёт информацию третьим лицам. Все данные — история, закладки, cookie, настройки — хранятся исключительно на устройстве пользователя в папке профиля приложения. Пользователь имеет полный контроль над своими данными и может удалить их в любой момент.»
