# Приватность и 152-ФЗ

## Коротко

Браузер **не собирает персональные данные**. Нет телеметрии, аналитики, отчётов об ошибках. Всё работает и хранится **только на устройстве пользователя**.

## Что где хранится

### Локальные файлы (папка `userData`)

| Файл | Что внутри | Когда создаётся |
|---|---|---|
| `bookmarks.json` | Закладки и папки | При добавлении закладки |
| `history.json` | История посещений | При навигации (кроме приватных вкладок) |
| `downloads.json` | Список загрузок | При скачивании файла |
| `settings.json` | Тема, акцент, порядок кнопок тулбара, homepage, кастомная тема, настройки блокировки | При изменении настроек |
| `session.json` | Открытые вкладки для восстановления | Если включено восстановление сессии |
| `Extensions/` | Установленные расширения Chrome | При установке расширения |

**Пути:**
- macOS: `~/Library/Application Support/malina-browser/`
- Windows: `%APPDATA%\malina-browser\`
- Linux: `~/.config/malina-browser/`

### Сессия Chromium

Cookie, кэш, localStorage, IndexedDB сайтов — хранятся во встроенной сессии Chromium там же, в `userData`. Отдельной приватной сессии — во временной, очищается при выходе.

**Ограничение размера кэша:** кэш Chromium ограничен **100 МБ** через `--disk-cache-size`. При превышении Chromium автоматически чистит лишнее. Дополнительно в настройках есть кнопка **«Очистить кэш»**.

### Данные, которые НИКОГДА не сохраняются на диск

| Данные | Где живут |
|---|---|
| «Недавно закрытые» вкладки | Только в RAM, стираются при выходе |
| PDF-документы во вьювере | Только в RAM, освобождаются при закрытии вкладки |
| Статистика блокировки трекеров | Только в RAM, сбрасывается при перезапуске |
| **Счётчик трекеров на текущей странице** | Только в RAM, сбрасывается при навигации и перезапуске |
| Кэш подсказок DuckDuckGo | Только в RAM, TTL 5 минут |
| Решения по разрешениям | Только в RAM, сбрасываются при перезапуске |

### localStorage

Используется для UI-настроек (тема до отрисовки страницы, размер шрифта в Reader Mode, ярлыки на стартовой, прогресс чтения PDF). Не содержит персональных данных.

## Чего НЕТ в проекте

- ❌ Телеметрии
- ❌ Аналитики (нет Google Analytics, Yandex Metrica)
- ❌ Автоматических отчётов об ошибках (нет Sentry, Bugsnag)
- ❌ Аккаунта пользователя
- ❌ Синхронизации с облаком
- ❌ Своего сервера
- ❌ Динамических списков трекеров
- ❌ Сбора данных установленных расширений разработчиком браузера

## Какие внешние запросы делает браузер

Три категории:

1. **DuckDuckGo Autocomplete API** — `https://duckduckgo.com/ac/?q=...`
   - Когда: при вводе в поисковую строку
   - Что отправляется: только текст запроса
   - Что НЕ отправляется: идентификаторы, куки

2. **DuckDuckGo Favicon Service** — `https://icons.duckduckgo.com/ip3/...`
   - Когда: при показе закладки, истории или ярлыка
   - Что отправляется: только домен сайта

3. **Chrome Web Store** — `https://clients2.google.com/...`
   - Когда: при установке или обновлении расширения Chrome
   - Что отправляется: ID расширения, IP-адрес пользователя, User-Agent, стандартные HTTP-заголовки
   - **Разработчик браузера не имеет доступа к этим запросам** — они идут напрямую от устройства пользователя к серверам Google
   - Цели обработки этих данных определяет Google, а не разработчик браузера

Все запросы — без аутентификации и пользовательских токенов.

## Дополнительные меры приватности

### Referrer Policy

Заголовок `Referer` **обрезается до origin**. Когда пользователь переходит с `https://example.com/private/page?token=abc` на внешний сайт, в заголовке `Referer` уходит только `https://example.com/` — без пути и параметров.

**Что это даёт:**
- Сайты-получатели не видят конкретную страницу, с которой пришёл пользователь
- Устраняется утечка чувствительных данных через URL (токены, ID сессий, query-параметры)
- Работает на уровне сессии Chromium через `webRequest.onBeforeSendHeaders`

### Защита от WebRTC IP leak

WebRTC отключён от локальных сетевых интерфейсов через `webrtc-ip-handling-policy: 'default_public_interface_only'`. Сайты через WebRTC видят **только публичный IP** пользователя, но не локальный (`192.168.x.x`, `10.x.x.x`).

**Что это даёт:**
- Сайты и рекламные сети не могут определить локальную сеть пользователя
- Устраняется вектор деанонимизации через WebRTC

### HTTPS-only режим

Переключатель в **Настройки → Приватность**. Когда включён — все HTTP-сайты блокируются на warning-странице без возможности перейти.

**Что это даёт:**
- Защита от перехвата данных в незащищённых сетях (публичный Wi-Fi, гостевая сеть)
- Пароли, куки и содержимое страниц не могут быть перехвачены провайдером
- Никаких смешанных HTTP-запросов с HTTPS-сайтов

### Индикатор блокировки трекеров

В адресной строке показывается счётчик заблокированных трекеров на текущей странице — например, «🛡 5».

**Что хранится:**
- Только агрегированное число на вкладку
- Хранится в `Map<webContentsId, count>` в main-процессе
- Сбрасывается при навигации и при перезапуске
- **Сами URL трекеров в UI не показываются**, в логах — только при `DEBUG=1`

### Защита от `data:` в mainFrame

Все переходы на `data:`-URL в главном фрейме блокируются на уровне сессии. Эта защита **работает всегда**, независимо от настроек блокировки трекеров.

### Приватный режим

В приватных вкладках используется **отдельная сессия Chromium** с изолированными cookie, кэшем и localStorage. При выходе из браузера данные приватной сессии **полностью очищаются** — гарантированно, через `before-quit` с `await clearPrivateData()`. Дополнительно очистка запускается при следующем запуске — на случай краша или принудительного завершения процесса.

История посещений в приватном режиме **не записывается**. Приватные вкладки **не попадают в «Недавно закрытые»**.

### Блокировка трекеров и рекламы

Браузер блокирует трекеры и рекламу на **двух уровнях**:

1. **По доменам** — ~500 известных трекерных и рекламных доменов, разбитых на 6 категорий:
   - Реклама (doubleclick.net, googlesyndication.com, criteo.com)
   - Аналитика (google-analytics.com, mc.yandex.ru, hotjar.com)
   - Соцсети (connect.facebook.net, platform.twitter.com)
   - Маркетинг (hubspot.com, mailchimp.com)
   - Fingerprint (fpjs.io, threatmetrix.com, maxmind.com)
   - Криптомайнеры (coinhive.com, coinimp.com)

2. **По URL-паттернам** — блокируются запросы, у которых путь похож на рекламный (`/ads/`, `/adserver/`, `/pagead/` и т.д.)

**Категории включаются/выключаются** отдельно в настройках.

Список доменов — **статический**, в `src/main/tracker-list.js`. **Не загружается из интернета** — это осознанное решение: динамические списки делают регулярные запросы к внешним серверам и раскрывают IP пользователя.

Заблокированные запросы **не отправляются** никуда — они отменяются до выхода из приложения.

## Расширения Chrome

Браузер поддерживает установку расширений из официального Chrome Web Store. Эта функция — **инструмент**, а не сервис: разработчик браузера не контролирует и не имеет доступа к тому, что делают установленные расширения.

### Какие расширения работают

Из-за ограничений Electron (фреймворка, на котором построен браузер) поддерживается **только подмножество Chrome Extension API**:

- ✅ **Работают:** расширения на Manifest V3, использующие `content_scripts`, `declarativeNetRequest`, `chrome.storage`. Например — **uBlock Origin Lite** (блокировка рекламы).
- ❌ **Не работают:** расширения на Manifest V2, использующие `chrome.tabs`, `chrome.webRequest` (блокирующий), `chrome.action`. Например — классический uBlock Origin.

Перед установкой расширения стоит проверить его совместимость.

### Ответственность за расширения

Установленные расширения — это **сторонний код**, который пользователь устанавливает самостоятельно. Расширения могут:
- Получать доступ к содержимому открытых страниц
- Собирать данные о посещаемых сайтах
- Передавать данные их авторам
- Встраиваться в интерфейс страниц

**Разработчик браузера:**
- Не контролирует действия установленных расширений
- Не имеет доступа к данным, которые они собирают
- Не несёт ответственности за их поведение и политику конфиденциальности

**Пользователь:**
- Устанавливает расширения на свой страх и риск
- Самостоятельно решает, каким расширениям доверять
- Может удалить любое расширение в любой момент через страницу `internal://extensions`

При установке расширения браузер показывает предупреждение об этих рисках.

### Что хранится локально

Установленные расширения распаковываются в `userData/Extensions/`. Их файлы и данные (`chrome.storage`) хранятся **только на устройстве пользователя** и не передаются разработчику.

### Внешние запросы при установке расширений

При установке или обновлении расширения браузер обращается к серверам Chrome Web Store (Google). В этих запросах передаётся:
- ID устанавливаемого расширения
- IP-адрес пользователя
- User-Agent
- Стандартные HTTP-заголовки

**Разработчик браузера не видит эти запросы и не имеет к ним доступа.** Ответственность за обработку этих данных на стороне магазина лежит на Google.

## Соответствие 152-ФЗ

**Федеральный закон № 152-ФЗ «О персональных данных»** регулирует деятельность **операторов персональных данных**.

**Malina Browser не является оператором ПД, потому что:**

1. **Не собирает** ПД — нет форм регистрации, нет телеметрии, нет логирования
2. **Не обрабатывает** ПД — вся работа с данными происходит на устройстве пользователя
3. **Не передаёт** ПД третьим лицам — нет серверов
4. **Не имеет доступа** к ПД — данные хранятся в `userData`, разработчик их не видит
5. **Не собирает данные расширений** — устанавливаемые расширения работают локально и являются сторонним кодом

### Cookie и 152-ФЗ

Cookie, которые сохраняют сайты в браузере:
- Хранятся в изолированной сессии Chromium
- Не логируются, не отправляются разработчику
- Управляются через **Настройки → Приватность → Cookie-менеджер**

Пользователь может просматривать cookie по доменам, создавать, редактировать, удалять, а также **полностью очищать данные сайтов** (cookies + localStorage + IndexedDB + service workers + кэш) одной кнопкой.

### IP-адрес и 152-ФЗ

Роскомнадзор придерживается широкой трактовки и относит IP-адрес к персональным данным, если по нему можно косвенно определить человека.

**В контексте Malina Browser:**
- Браузер сам по себе **не логирует и не хранит** IP-адреса пользователей
- IP передаётся **напрямую** серверам Chrome Web Store при установке расширений — разработчик браузера к этим запросам доступа не имеет
- Цели обработки этих данных определяет Google, а не разработчик

Таким образом, разработчик Malina Browser **не является оператором ПД**, связанных с IP-адресами при установке расширений.

## На счет приватности

> «Проект не собирает пользовательские данные, не имеет серверной части, не передаёт информацию третьим лицам. Все данные — история, закладки, cookie, настройки — хранятся исключительно на устройстве пользователя. Пользователь имеет полный контроль над своими данными и может удалить их в любой момент. Установленные расширения Chrome являются сторонним кодом — разработчик браузера не контролирует их действия и не имеет доступа к собираемым ими данным.»
